# Autodrome v0.2.0

Autodrome 0.2 improves installation, album review, recovery and publication history
for the self-hosted FastAPI + Vue application.

## Highlights

- Install a Python wheel containing the compiled frontend, or use Docker Compose
  with the `ghcr.io/raposo93/autodrome:0.2.0` image for Linux amd64.
- Review playlists and MusicBrainz editions in separate Dashboard, Select and
  Review screens. Compare titles and durations, inspect edition details, and
  check the library destination before queueing.
- Prepare alternative artwork from a playlist thumbnail or an uploaded image,
  with explicit square fit/crop confirmation when archive artwork is absent.
- Cancel queued or active jobs, retain recoverable failures and inspect system
  diagnostics from the web interface.
- Keep durable publication provenance: playlist manifest, release metadata,
  track mapping, artwork decisions, application version and SHA-256 checksums.
  Recreate historical decisions in Review without automatically queueing work.
- Download tracks sequentially by default, with optional concurrency from 1 to 4.
- Harden WebSocket authentication, MusicBrainz searches, logging and yt-dlp's
  JavaScript runtime configuration. Redis remains optional.

## Integrity and recovery

Albums are validated in staging before publication. Existing library content
remains protected against overwrites. Fault-injection, disk-full, process-kill,
reboot and reproducible chaos campaigns are documented in the repository.

The final pre-release fixes preserve publication history when an album is moved
or removed and its destination is reused (#68), and require fresh confirmation
of alternative artwork when recreating a review (#69). Cover Art Archive cache
files are stored outside the installed Python package. The final audit also
blocks legacy artist-directory aliases before publication and bounds temporary
and final track filenames by filesystem byte limits.

## Installation and upgrades

See [Docker Compose](https://github.com/Raposo93/autodrome/blob/v0.2.0/docs/docker.md)
or [native/systemd installation](https://github.com/Raposo93/autodrome/blob/v0.2.0/docs/installation-native.md).
Native installation requires Python 3.14, ffmpeg and the documented yt-dlp runtime.

Before upgrading, stop the service and back up the library, staging, queue,
publication catalog, prepared covers and configuration. Existing schema-1
publication catalogs migrate transactionally to schema 2 on startup, preserving
history while allowing successive publications at a freed destination. Older
binaries cannot read schema 2; retain the pre-upgrade backup for a rollback.

## Validation and limits

The pre-release checks passed 406 backend tests, 41 frontend tests and 22 browser
E2E tests, plus frontend build and installed-wheel smoke tests. Providers are
controlled in automated tests; this final review did not repeat live downloads
or a host reboot. Container validation runs in CI and the release workflow.

One backend process and one active album are supported. Track matching is advisory
and does not identify audio or reorder playlists. Cancellation may wait for an
active operation and is blocked once publication begins. Manual metadata uses
YouTube titles and order, without a per-track editor or MusicBrainz artwork.
Provider outages can prevent completion. An interrupted publication may already
have created the album: inspect the library and history before retrying.
