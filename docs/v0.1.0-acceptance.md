# v0.1.0 acceptance record

Date: 2026-09-09–10. Scope: FastAPI backend and compiled Vue frontend, one backend
process, sequential audio downloads, Redis disabled. Tests used an isolated
library, staging root and queue under `/tmp`, separate from the normal library.

## Automated validation

`./check.sh`: 165 backend tests, 21 frontend tests and the Vite production build
passed. Tests include queue storage recovery, numeric audio identity around
99/100/101 tracks, track/album credits, progressive hydration, selected-playlist
preflight, explicit manual metadata, progress, and shutdown draining.

## Production and UI

The documented `start_autodrome.sh --production` entry point ran under systemd.
The example unit was adapted to the existing non-root user, checkout path and an
isolated environment file, and registered temporarily in the user manager. This
validates foreground execution and process lifecycle; it is not a machine reboot
test or an installation into `/etc/systemd/system`.

Verified: start, status, restart, stop, journal logs, index and direct SPA route
responses, API authentication endpoint, WebSocket initial snapshot and heartbeat.
The same production entry point was then verified from a clean archive of the
tracked source after installing `requirements.lock` and `frontend/package-lock.json`:
the index, direct SPA route, authentication and health endpoints returned HTTP 200,
and the authenticated WebSocket returned an empty snapshot followed by `pong`.
The browser showed progressive tracklists, selected-release priority, isolated
provider failures, real download progress and terminal states. A new search
cleared selections; rapid playlist changes retained the latest selection. Manual
mode required confirmation and displayed blank metadata fields independent of the
search terms. The existing-album rejection was submitted through that form.

## Deliberately deferred

#36 (queued cancellation) remains post-0.1.0: its interaction with a pending initial
state write requires additional race handling and is not a release blocker.
#29 and #38–#45 remain outside this release. No performance, disk-full, SIGKILL,
reboot or chaos guarantees are claimed from these acceptance tests.

Dependency auditing reports pre-existing npm advisories. They were not silently
suppressed or changed during functional acceptance; dependency maintenance remains
a follow-up, and this release should not be described as vulnerability-free.
